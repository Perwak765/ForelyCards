# ForelCards — GitHub Pages static version

Ця версія не використовує Supabase і не зберігає каталог у `localStorage`.
Єдине спільне джерело карток — файли в GitHub-репозиторії:

- `cards/cards.json` — метадані карток;
- `cards/images/*.webp` — зображення.

Тому після commit/push усі відвідувачі GitHub Pages бачать один і той самий каталог.

## Як додати 500+ карт

1. Поклади WebP-файли в `incoming/`.
2. Відкрий `metadata.csv`. Для кожного файла можна вказати:
   `filename,character,rank,platform,description,link,date`.
3. Якщо `metadata.csv` не містить конкретного файла, ім'я персонажа береться з назви файла, ранг — `A rank`, площадка — `Авторские`.
4. Запусти з кореня репозиторію:

```bash
python tools/build-cards.py
```

5. Скрипт скопіює всі WebP у `cards/images/` і створить/оновить `cards/cards.json`.
6. Зроби commit/push у GitHub.
7. GitHub Pages автоматично опублікує новий каталог.

Імпортер дозволяє до 5000 WebP за один запуск, тому вимога 500 карт не є проблемою.

## Важливо для GitHub

GitHub має обмеження на розмір окремого файла (100 MB для звичайного GitHub). Для великої кількості важких WebP краще оптимізувати зображення або використовувати Git LFS/інше сховище. Для звичайних WebP-карт невеликого розміру 500 карт зазвичай нормально поміщаються в репозиторій.

## Пошук і фільтри

- Пошук працює **тільки за ім'ям персонажа**.
- Великого списку персонажів у фільтрах немає.
- Фільтри залишені тільки для площадки та рангу.

## Чому немає кнопки «зберегти карту» прямо на сайті

GitHub Pages — статичний хостинг. JavaScript у браузері не має права записувати нові файли в GitHub-репозиторій. Тому додавання виконується через `incoming/` + `build-cards.py`, після чого зміни пушаться в GitHub.
